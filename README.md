# midmanstudio-ai-toolkit

A curated, tool-agnostic AI skills toolkit — not limited to one AI assistant,
and not limited to one language. **DixScript is the flagship, highest-priority
content**; everything else gets added on top of that foundation, deliberately,
one skill at a time.

This is not a mirror of any single upstream project. It's built by pulling in:

- **DixScript skills** (highest priority, first-party) — everything an AI
  assistant needs to read, write, and scaffold `.mdix` files correctly.
  Sourced from [`DixScript-Rust`](https://github.com/Mid-D-Man/DixScript-Rust)
  and [`mdix-scaffold`](https://github.com/Mid-D-Man/mdix-scaffold).
- **General free/usable skills**, curated a few at a time as they're actually
  needed — language patterns (Rust, C#/Unity, TypeScript/Svelte,
  Blazor/.NET) and cross-cutting workflow skills (git, testing, review) —
  some adapted from
  [`everything-claude-code`](https://github.com/affaan-m/everything-claude-code)
  (MIT), leaving out its paid "Pro" GitHub App and multi-harness tooling,
  neither of which is relevant here.

## Not Claude-specific

Every skill here is a plain markdown file with YAML frontmatter — no
Claude-specific format, no API dependency, nothing that only works inside
one tool. Point any AI coding assistant that can read local files at the
relevant `SKILL.md`, paste its contents into a chat, or drop the folder into
whatever convention that tool uses (`.claude/skills/`, `.cursor/rules/`,
a Codex `AGENTS.md` reference, or just a pinned file in context).

## Structure

```
skills/
  dixscript/                  Flagship -- DixScript (.mdix) language & tooling
    dixscript-writing/        Core .mdix language reference -- syntax, types, style, common mistakes
    dixscript-scaffold/       mdix-scaffold usage -- templates, patch ops, replacements, workflows
    dixscript-raw-section/    @RAW section spec (deferred feature, not yet implemented in v1.0.0)
  languages/                  Per-language patterns -- one skill folder each, added as needed
    rust/
    csharp_unity/
    typescript_svelte/
    dotnet_blazor/
  workflow/                   Cross-cutting skills (git, testing, review) -- added as needed

references/
  dixscript/
    midx.ebnf                  Full formal grammar for DixScript v1.1.0

.mdix/                        The scaffold templates that generate this repo's own skeleton
  project_structure/
    project_structure.mdix     Directory shape -- category folders, .gitignore
  replacements/
    replacements.mdix          Real content -- README, skills, grammar, CI workflows

.github/workflows/            CI wiring for re-running the scaffold (workflow_dispatch, gated)

CONTRIBUTING.md               Skill format spec + rules for what goes in this repo
NOTICE.md                     Attribution for anything adapted from third-party sources
```

`languages/` and `workflow/` are scaffolded but currently empty (just a
`.gitkeep` each) — nothing gets ported in speculatively. See
`CONTRIBUTING.md` for the actual shortlist.

## Why this exists

`everything-claude-code` is a large, actively-maintained plugin — 67 agents,
284 skills, 94 legacy command shims as of v2.2.0 — built for a much bigger
scope than one person needs: a full multi-harness "agent operating system"
with a paid hosted tier, and it's explicitly a Claude Code plugin first. Most
of that doesn't apply here. This repo exists to hold **just the skill content
that's actually useful, in a format any assistant can read**, kept current
with my own projects (DixScript, Mid Engine, MidManStudio Unity packages)
first, and general-purpose dev skills second — added deliberately, not
wholesale.

## Using these skills

Each `skills/<category>/<name>/SKILL.md` is self-contained: YAML frontmatter
(`name`, `description`, `origin`) followed by plain markdown. Point any
assistant at the relevant file(s) for a task, or copy the folder into a
project's own conventions.

## Built with its own tooling

This repo's own skeleton is generated by `mdix-scaffold`, not hand-placed:
`.mdix/project_structure/project_structure.mdix` lays out the folder shape,
`.mdix/replacements/replacements.mdix` drops in the real content (this
README, the skills, the grammar reference, the CI workflow files). Re-run
the structure template after adding a new category folder instead of
hand-maintaining the tree. See
`skills/dixscript/dixscript-scaffold/SKILL.md` for exactly how that works,
including how `.github/workflows/` — a hidden path — gets populated through
`replacements/`'s `overrides::` mechanism despite replacements always
skipping dot-prefixed folders in its own source tree.
